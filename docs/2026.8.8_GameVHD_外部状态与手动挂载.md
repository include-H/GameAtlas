# GameVHD 外部状态目录与手动挂载说明

## 1. 状态目录策略

`box.json` 仍然放在差分 VHD 内的 `GameData`，因为它是本次运行的状态机文件，不应该被 Syncthing 在多台电脑之间同时修改。

`game_data_root` 为空时，runtime 使用：

```text
<挂载盘符>:\GameData
```

设置 `game_data_base` 后，runtime 会在父目录下追加一个游戏目录：

```json
{
  "game_data_root": "",
  "game_data_base": "D:\\GameAtlas",
  "game_data_name": "地平线",
  "registry_hive": ""
}
```

最终状态根为：

```text
D:\GameAtlas\地平线
```

`game_data_name` 为空时，runtime 从 manifest 的 `base_vhd` 文件名去掉扩展名；例如 `地平线.vhd` 推导为 `地平线`。`registry_hive` 为空时跟随最终状态根：

```text
D:\GameAtlas\地平线\Registry\user.dat
```

旧版显式填写的 `game_data_root` 和 `registry_hive` 仍然优先，保持兼容。

## 2. Syncthing 边界

Syncthing 只负责复制最终状态根，Hook 负责把游戏写入导向该根目录。不要让两台电脑同时运行同一个游戏状态根。游戏退出、hive 卸载并且 Syncthing 完成同步后，才切换到另一台电脑。

日志、Temp、崩溃转储、NVIDIA shader cache 等机器相关内容不适合当作跨机器状态。后续可通过 ignore 规则排除；注册表 hive 在游戏运行期间也不能被 Syncthing 同步覆盖。

## 3. 为什么不要双击差分 VHD

差分 VHD 的 parent 是 SMB 上的 UNC 路径。资源管理器双击 VHD 时，可能在 parent SMB 会话建立之前调用系统 attach。此时磁盘管理器可能显示初始化提示，即使 parent 中实际有分区，runtime 也能正常挂载并运行游戏。

当前已确认的事实是：目标 VHD 能看到分区、自动挂载成功、游戏能运行。因此不能执行初始化或格式化；那会把正常的差分链当成空磁盘处理。

正确的手动入口是先连接 SMB，再调用 runtime：

```powershell
.\mount-manual.ps1 `
  -RuntimeExe .\gamevhd-runtime-x64.exe `
  -DiffVhd 'C:\GameAtlas\diff\地平线.vhd' `
  -SmbUnc '\\192.168.1.4\game1' `
  -ParentUnc '\\192.168.1.4\game1\地平线.vhd' `
  -SmbUser 'read' `
  -SmbPass '<password>' `
  -Letter G
```

这个脚本不会调用 `diskpart initialize`、`format` 或任何写入 parent 的操作。

## 4. 验收

挂载验收看：

```text
[MOUNT-OK] G:
```

Hook 验收看会话日志中的：

```text
HOOK_DLL_PRESENT
RULES_LOADED 12
REG_REWRITE
FILE_REWRITE
FILE_READTHROUGH
FILE_DIRECTORY_MERGE
```

仅看到 `HOOK_DLL_PRESENT` 或 `REG_REWRITE`，不能证明真实游戏文件配置已经重定向。真实 HZD 需要另外看到 `FILE_REWRITE src=... dst=...`，目录同时存在宿主与沙箱内容时还应看到 `FILE_DIRECTORY_MERGE`，并用文件监控确认宿主源路径没有新的游戏写入。
