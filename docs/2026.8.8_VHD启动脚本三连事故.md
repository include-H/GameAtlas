# 2026.8.8 VHD 启动脚本三连事故排错记录

> 从"BAT 内嵌 PowerShell"到"bat 引导壳 + 纯 PS 主脚本"的重写过程中，真机连续暴露三个独立 bug。本文按排错方法论记录：现象 → 被推翻的假设 → 真根因 → 方案 → 测试矩阵。

## 背景

原启动脚本是 Go 服务端生成的 Windows BAT（`windows_launch.go` 字符串拼接），客户端管理员运行：SMB 连接 → 创建/复用差分盘 → diskpart 挂载 → 游玩后卸载清理。本次重写目标：PS 主脚本（彩色菜单、SMB 复用、盘符 diff、exe 扫描、存档跳转）。

## Bug 1：PowerShell 5.1 `意外的标记"^"`

**现象**：exe 扫描阶段报 `表达式或语句中包含意外的标记"^"`，随后"未找到可执行文件"。

**被推翻的假设**：误以为 BAT 内嵌 PowerShell 的所有管道都要 `^|` 转义。

**真根因**：cmd 对 `|` 的转义规则**取决于上下文**——
- `for /f '...'` 单引号命令：cmd **不保护** `|`，必须 `^|` 转义（盘符查找那行一直正确）；
- 普通 `powershell -Command "..."` 双引号参数：cmd **保护** `|`，写 `^|` 会把字面 `^` 原样传给 PowerShell 5.1 → ParserError。

两处规则相反，改一处漏一处。

**方案**：整体重写为纯 PS，消除 cmd 解析层（见"架构变更"）。

## Bug 2：盘符查找失败（`游戏盘符： :` 空值）

**现象**：`游戏盘符： :` —— GAME_DRIVE 为空但走了"已找到"分支。

**被推翻的假设**：盘符查找逻辑没问题，只是匹配不到。

**真根因**（两层）：
1. `set "GAME_DRIVE="` 预初始化后，`if defined GAME_DRIVE` **恒真**（cmd 的 `defined` 对空值也返回真）——这是"空值但走已找到分支"的直接原因；
2. 原查找方案 `Get-Disk | Where-Object { $_.Path -match DIFF_NAME }` 不可靠：`Get-Disk.Path` 是设备路径（`\\?\scsi#...`），**不含 vhdx 文件名**，永远匹配不到。

**方案**：挂载前后 `Get-Partition` 盘符快照 diff，新增盘即为游戏盘。

## Bug 3：VHD 挂载失败 0x80070057（三连踩：编码 + PS 数组解析坑）

**现象**：`VHD 挂载失败，错误码 -2147024809`（0x80070057 ERROR_INVALID_PARAMETER）。基础盘是中文路径 + 老格式 `.vhd`。

**被推翻的假设**（依次）：
1. ~~diff 盘格式不匹配~~（.vhd parent 配 .vhdx diff 确实 ERROR_FILE_CORRUPT，但脚本 diff 名继承基础盘扩展名，天然匹配）；
2. ~~UNC parent 不被 create vdisk 支持~~（微软官方文档确认差分盘 parent 可放远程共享）；
3. ~~`-Encoding Default`(GBK) 可行~~（真机仍失败）；
4. ~~`-Encoding Unicode`(UTF-16LE+BOM) 可行~~（diskpart 返回 0 但**无命令回显**、不建 VHD——diskpart 对 UTF-16 脚本直接忽略）。

**真根因（两层叠加）**：

1. **PS 5.1 的 `@(...)` 多行数组解析坑**（决定性）：`$lines = @('a' + $x + 'b', 'c' + $y + 'd', ...)` 多行数组 + 字符串拼接，PS 5.1 会把三行独立元素解析成**一个字符串**（`System.Object[]` 但 `Count=1`，三个命令被空格拼成一行）。诊断命令实锤：`$lines.Count → 1`。diskpart 收到 `create vdisk ... select vdisk ... attach vdisk` 一行 → 当作单条命令解析 → 不建文件、返回 0。
2. **diskpart `/s` 脚本编码**：diskpart 只认 **ANSI（GBK/系统代码页）** 脚本——原始 BAT 用 GBK 能执行到挂载；UTF-16 脚本被忽略（返回 0 无回显）；UTF-8 脚本乱码回退帮助列表。

**方案（最终正解，真机闭环验证通过）**：
- **`List[string]` 逐行 `.Add()`** 替代 `@(...)` 多行数组——每条命令独立成行，避开 PS 5.1 解析坑；
- **`[System.IO.File]::WriteAllLines($dp, $scriptLines, [System.Text.Encoding]::GetEncoding(936))`** 写 GBK——diskpart 唯一认的格式（UTF-16 被忽略）；
- **PS 主脚本统一 CRLF**（`strings.ReplaceAll` 归一）——PS 5.1 对 LF 换行的多行结构解析异常；
- 保留**命令数/字节数/退出码日志**（`[脚本命令数]`），排错可见。}

## 架构变更（消除 Bug 1/2 的根因）

```
.bat（全 ASCII 引导壳）        .ps1（PowerShell 主脚本）
├─ fltmc 检测管理员             ├─ 彩色菜单（Write-Host）
├─ 非管理员 → RunAs 提权重启    ├─ SMB 复用（net use 检测）
├─ 读最后一行 base64            ├─ 盘符 diff（挂载前后 Get-Partition 对比）
├─ 解码写临时 .ps1 → 执行 → 删除 ├─ diskpart 挂载（diff 盘不存在则创建）
└─ 结束清理                     ├─ exe 自动扫描（限深3/排除安装器/多候选选择）
                                ├─ 存档目录跳转（模板变量展开）
                                └─ 卸载 + 清理凭据
```

- **bat 壳全 ASCII**：彻底消灭 GBK 编码层（downloads.go 已删 simplifiedchinese 转码）；
- **PS 主脚本 UTF-16LE+BOM → base64**：PS 5.1 中文完美解码，base64 对传输编码免疫；
- **转义地狱归零**：纯 PS 无 cmd 双层转义。

## 教训

1. **cmd 的 `^|` 转义取决于上下文**（for/f 单引号 vs 双引号参数），两处规则相反——能在 PS 里做就别在 BAT 里嵌 PS；
2. **`if defined VAR` 对空值恒真**——检查空变量用 `if not "%VAR%"==""`；
3. **PS 5.1 的 `@(...)` 多行数组 + 字符串拼接会被解析成单元素**——多行命令列表用 `List[string]` 逐行 Add，别用数组字面量；
4. **给 diskpart 写脚本，编码必须是 ANSI(GBK)**：UTF-16 被静默忽略（返回 0 无回显），UTF-8 乱码回退帮助，只有 GBK/ANSI 真机跑通；
5. **PS 5.1 脚本统一 CRLF**：LF 换行会导致多行结构解析异常；
6. **诊断命令是最好的取证**：`$lines.GetType()` + `$lines.Count` 一跑，直接看出数组被解析成单元素——比反复猜编码快得多；
7. **排错看证据不看假设**：手动交互键盘输入成功 vs 脚本文件失败，差异锁定"文件读取"这一个变量。
