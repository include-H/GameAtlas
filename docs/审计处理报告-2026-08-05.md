## 三、已处理问题

### 1. 「刷新文件大小」只补 NULL，从不刷新已登记文件（必须改 → 已改）

**问题**：设置页写的是"扫描游戏目录并更新数据库中的文件大小信息"，但 `RefreshFileSizes` 只查询 `size_bytes IS NULL` 的文件，文件被替换/增大后数据库中的旧大小永远不会更新；`UpdateSizeBytes` 是无生产调用的残留方法。

**处理**：
- [game_files.go](../backend/internal/repositories/game_files.go) 将 `ListFilesWithoutSize` 改为 `ListAll`（不再过滤 NULL，按 id 排序）；
- [game_file_refresh.go](../backend/internal/services/game_file_refresh.go) 改为刷新全部已登记文件，并补充行为注释；
- 删除无调用的 `UpdateSizeBytes`；
- 新增 [game_file_refresh_test.go](../backend/internal/services/game_file_refresh_test.go)：覆盖"已有大小也会被刷新覆盖"与"缺失文件计入 errors"两条行为边界。

### 2. 游戏店 N+1 拉详情，批量预告片接口无人使用（建议改 → 已改）

**问题**：`GameStoreView.loadStoreSession` 随机取 20 个游戏后逐个 `getGameDetail` 直到找到第一个带视频的游戏，最多 20 次串行请求；后端专为游戏店设计的 `GET /api/games/preview-videos` 从未被前端调用。

**处理**：
- [games.service.ts](../frontend/src/services/games.service.ts) 新增 `getPreviewVideos(publicIds)`，一次请求批量取回预告片；
- [GameStoreView.vue](../frontend/src/views/GameStoreView.vue) `loadStoreSession` 改为一次批量请求，取第一个有视频的结果；
- [games.service.test.ts](../frontend/src/services/games.service.test.ts) 新增批量拉取与空 id 短路两条测试。

### 3. 生产代码残留 console.log 与全局调试工具（必须改 → 已改）

**问题**：游戏店 `onMounted` 把 `window.__waifuTools` 挂到全局，`report()` 内有 `console.log`，违反风格约定 3.5 与审计基线"生产代码无 console 残留"。

### 4. SteamGridDB 出站请求不走 PROXY（建议改 → 已改）

**问题**：SteamService 与 AssetStore 都显式使用 `cfg.Proxy`，而 `NewSteamGridDBService` 只接收 API Key，使用默认 Transport 直连；在"Steam 需代理才能访问"的网络环境下 SteamGridDB 必然失败。

**处理**：[steamgriddb_service.go](../backend/internal/services/steamgriddb_service.go) 构造函数新增 `proxy` 参数并构建代理 Transport；[router.go](../backend/internal/http/routes/router.go) 传入 `cfg.Proxy`。

## 七、追加处理：告警层级与错误提示增强（2026-08-05）

处理用户反馈的两类前端问题：

### 1. 告警被编辑弹窗黑色遮罩遮挡

**根因**：`AlertBanner` 虽是 `position: fixed`，但渲染在 `.content` 内部；`.content` 自带 `position: relative; z-index: 1`，会形成独立堆叠上下文，把告警的 `z-index: 1000` 困在内容区内部。Arco 弹窗/抽屉渲染在 body 层（z-index 1001），因此编辑游戏时黑色遮罩盖住了右上角告警。

**处理**（[AlertBanner.vue](../frontend/src/components/AlertBanner.vue)）：
- 用 `<Teleport to="body">` 把告警容器提升到 body，脱离页面内所有堆叠上下文；
- 容器 `z-index: 2000`，高于 Arco modal/drawer（1001）与 message/notification（1003）；
- 容器 `pointer-events: none`，空白区域不再拦截右上角按钮；告警卡片自身保留 `pointer-events: auto`，关闭按钮仍可点击；
- 补充移动端布局（左右留 12px）。

### 2. 补静默失败的错误提示

- [GameStoreView.vue](../frontend/src/views/GameStoreView.vue)：`loadStorePosters` / `loadStoreSession` 两个原静默 catch 分别补 warning（"海报加载失败，已显示兜底样式" / "游戏店数据加载失败，货架暂时为空"）；
- [ScreenshotCarousel.vue](../frontend/src/components/ScreenshotCarousel.vue)：视频 `@error` 时进入内联失败态，显示海报 + "视频加载失败"提示，替代一直转圈的加载器；切换媒体/数据刷新时自动复位。

## 八、追加处理：编辑保存后预告片不播放（2026-08-05）

**反馈**：详情页正在播放预告片时打开编辑并保存，刷新后预告片不再播放而是消失；手动切到截图再切回预告片才会恢复播放。

**根因**（[ScreenshotCarousel.vue](../frontend/src/components/ScreenshotCarousel.vue)）：
- 编辑保存后详情刷新会传入新的 props（视频 URL 通常不变），轮播无条件把 `videoReady` 重置为 `false`；
- 但 `<video>` 元素因 `currentMedia.key`（含 URL）未变而不会被重建，已加载/正在播放的视频不会再次触发 `canplay`/`playing` 事件；
- `videoReady` 控制视频 `opacity`（未就绪为 0），于是画面停在透明加载态——看起来就是"预告片消失"；切到截图再切回时元素被重建、事件重新触发，所以又能播放。

**处理**：
- 新增 [video-playback.ts](../frontend/src/utils/video-playback.ts)：仅在视频 URL 真正变化时重置播放状态；
- [ScreenshotCarousel.vue](../frontend/src/components/ScreenshotCarousel.vue) 的 `watch(currentMedia)` 视频分支按该规则复位 `videoReady` / `videoFailed` / `userUnmuted`；
- `tryPlayVideo` 增加 `readyState >= 2` 时直接恢复 `videoReady`，避免"已加载但事件不再触发"的卡透明态；
- 新增 [video-playback.test.ts](../frontend/src/utils/video-playback.test.ts) 锁定"URL 相同不复位、URL 变化复位"两条行为边界。

**验证**：前端 146/146 测试通过，lint / build 通过。

### 11.3 分页字段结论

- `/games` 普通列表：只依赖 `page`、`totalPages`、`pending_issue_counts`；已移除 `total`、`limit`。
- `/games?pending=true`：待处理中心传统分页仍使用 `total`、`limit`、`totalPages`、`pending_issue_counts`。
- `/games/timeline`：使用 `limit`、`hasMore`、`nextCursor`，不依赖 `total/totalPages`。
- `/series`、`/publishers` 与详情：继续使用 `page/limit/total/totalPages`，系列/发行商详情页需要 `total` 展示“共 N 部作品”。
