## 2. 问题重构

### 最初拆分的子问题

1. VHD 差分盘创建和挂载。
2. Windows 管理员权限和 SMB parent 访问。
3. 游戏 PE 位数与 DLL 位数匹配。
4. 主进程挂起启动与 DLL 注入。
5. 子进程继承和继续注入。
6. gvhook_init 初始化、MinHook 安装。
7. 注册表隔离。
8. 文件系统隔离。
9. hive 卸载和崩溃清理。
10. 真实路径级验收。

### 改变方向的关键判断

关键判断是：

HOOK_DLL_PRESENT != 文件沙箱成功
RULES_LOADED 12 != 所有游戏状态已隔离
游戏启动成功 != 游戏配置写进 GameData

这个判断来自真实文件监控结果。

游戏运行时，宿主仍然出现了：

C:\Users\Hao\Documents\Horizon Zero Dawn Remastered\Horizon Zero Dawn Remastered.log
C:\Users\Hao\AppData\Roaming\Guerrilla Games\Horizon Zero Dawn Remastered\crs
C:\Users\Hao\AppData\Local\GameAtlas\logs\horizon-zero-dawn-remastered.log
C:\Users\Hao\AppData\Local\NVIDIA\DXCache\...

这直接证明当时只有注册表 Hook 或 DLL 注入成功，文件配置仍然写进了宿主 C 盘。

### 发现的错误前提

#### 1. 把注册表规则当成完整沙箱

runtime/src/rules.rs 初始规则主要针对：

Documents
Saved Games
AppData

但实际需求是：

游戏访问 C/D/其他本地盘时，除系统区和游戏自身 VHD 外都进入 GameData

因此补充了 NtCreateFile、NtOpenFile 等 NT 文件 API Hook。

#### 2. 把 NtCreateKeyEx 当成必需 API

真实日志：

REG_HOOK_RESOLVE_FAILED fn=NtCreateKeyEx
INIT_FAILED code=4 reason=gvhd_install_registry_hooks

后续改为可选 Hook 后，日志变成：

REG_HOOK_OPTIONAL_SKIPPED fn=NtCreateKeyEx
REG_HOOK_OPTIONAL_SKIPPED fn=NtCreateKeyTransactedEx
REG_HOOK_OPTIONAL_SKIPPED fn=NtDeleteKeyEx
RULES_LOADED 12
HOOK_DLL_PRESENT

这说明"所有可选 Nt API 必须存在"是错误不变量。

#### 3. game_id 为空时仍期待注册表规则

初期 POC 日志出现：

REG_HOOKS_SKIPPED reason=game_id_empty
RULES_LOADED 0
HOOK_DLL_PRESENT

这是参数配置问题，不是 MinHook 或游戏拒绝注入。完整 run 流程生成非空 game_id 后才出现 RULES_LOADED 12。

#### 4. 注册表目标路径缺少分隔符

旧日志：

dst=\REGISTRY\USER\GameVHD_horizon-zero-dawn-remasteredSoftware\...

正确语义应该是：

dst=\REGISTRY\USER\GameVHD_horizon-zero-dawn-remastered\Software\...

这个问题在 reg.c 中修复。

#### 5. Wine 虚拟 GPU 问题被误认为 Hook 问题

Wine 中出现：

Unhandled exception: page fault on execute access to 0x00000000f99d1660

同时环境是：

Wine build: wine-10.0
Host system: Linux

当时虚拟机使用 virgl，没有真实 D3D12 GPU。这个现象不能证明 Hook 失败，只能证明该环境不适合验证 HZD 的真实 GPU 初始化。

## 3. 关键证据

### 3.1 Wine 环境证据

Wine 模块列表里可以看到：

PE  6ffff99d0000-6ffff9a16000  gvhook-x64
PE  140000000-14a4ed000          horizonzerodawnremastered

这证明 Wine 进程中 DLL 确实加载了，但随后 GPU/游戏初始化阶段崩溃。因此 Wine 只适合做 Hook 合成测试，不适合证明 HZD 真正能玩。

### 3.2 Windows 真机注入证据

真实 Windows 使用过：

.\gamevhd-runtime-x64.exe inject-poc `
  --exe "G:\HorizonZeroDawnRemastered.exe" `
  --work-dir "G:\" `
  --hook "C:\Users\Hao\Desktop\gamevhd-real-gpu-test\gvhook-x64.dll" `
  --log "$env:TEMP\hzd-hook.log" `
  --mode early-bird

曾经出现过：

gvhook_init 返回非零: 5

hook_common.h 中 5 对应：

GVHD_INIT_ERR_LOG

也就是 Hook 日志文件无法创建或打开。

修正日志路径并使用完整 --mode early-bird 后，游戏能够启动。

Windows 日志中出现：

CHILD_INJECTED pid=18004

这确认了子进程注入路径实际执行。

### 3.3 注册表 Hook 证据

完整运行日志出现过：

RULES_LOADED 12
HOOK_DLL_PRESENT
REG_HKLM_ACCESS \Registry\Machine\System\CurrentControlSet\Control\ComputerName
REG_REWRITE src=\REGISTRY\USER\S-1-5-21-...\Software\Microsoft\Windows\CurrentVersion\Explorer\Shell Folders ...
REG_READTHROUGH \REGISTRY\USER\S-1-5-21-...\Software\Microsoft\Windows\CurrentVersion\Explorer\Shell Folders

这证明：

- DLL 已加载。
- 规则表已生成。
- 注册表 API 已命中。
- HKCU 路径出现了重写和读取回退。

### 3.4 文件重定向未完成前的反证

文件监控捕获到了：

Changed C:\Users\Hao\Documents\Horizon Zero Dawn Remastered\Horizon Zero Dawn Remastered.log
Changed C:\Users\Hao\AppData\Roaming\Guerrilla Games\Horizon Zero Dawn Remastered\crs
Changed C:\Users\Hao\AppData\Local\Temp

但当时没有出现对应的：

FILE_REWRITE

因此旧版本不能称为完整文件沙箱。

### 3.5 新文件 Hook 的合成测试证据

新版本在 Wine 测试程序中验证了：

C:\users\hao\Documents\hzd.ini
 -> G:\GameData\Users\hao\Documents\hzd.ini

D:\SomeApp\state.dat
 -> G:\GameData\HostDrives\D\SomeApp\state.dat

同时：

宿主目录没有生成文件
测试返回 [INJECT-OK]

这证明 file.c 的路径映射逻辑可以工作，也证明 D 盘路径进入了沙箱映射。

但这仍然不是 HZD 本体的真实命中证据。

### 3.6 VHD 证据

历史真机验收记录中确认：

CreateVirtualDisk 成功
AttachVirtualDisk 成功
GetVirtualDiskPhysicalPath -> \\?\PhysicalDrive1
Get-Disk 显示 Msft Virtual 58GB MBR
卷 GUID 能匹配到目标物理盘
SetVolumeMountPoint 分配盘符成功
游戏可以从挂载盘启动

用户后来进一步确认：

- 磁盘管理能看到分区。
- 手动挂载能成功。
- 自动挂载不报错。
- 游戏能正常游玩。

因此目前没有证据表明 VHD 损坏或真的需要初始化。

## 4. 被排除的方案

| 方案 | 排除证据 | 最终处理 |
|---|---|---|
| 把 virgl/Wine VM 当作 HZD 最终验证环境 | HZD 在 GPU 初始化附近执行访问违规，宿主无真实 D3D12 GPU | 保留 Wine 做合成 Hook 测试，真实游戏改用 Windows 真机 |
| 只看 HOOK_DLL_PRESENT 判断成功 | 宿主 C 盘仍出现游戏配置文件 | 增加真实文件路径监控和 FILE_REWRITE 日志 |
| 让所有 Nt 注册表函数都必须存在 | NtCreateKeyEx 解析失败导致 INIT_FAILED code=4 | 可选函数改为跳过，核心函数仍必须成功 |
| 只 Hook 注册表 | Documents 和 AppData 仍写入 C 盘 | 增加 NtCreateFile、NtOpenFile、属性查询和删除 Hook |
| 用 DefineDosDeviceW 分配盘符 | API 返回成功但资源管理器看不到预期盘符，且产生残留 | 改用 SetVolumeMountPointW |
| 用 VHDX 参数创建 VHD | CreateVirtualDisk 返回 0x570 | 按 .vhd/.vhdx 选择 Version 1/2 参数结构 |
| VHD Version 1 参数直接照搬 Version 2 布局 | 返回 0x5 ACCESS_DENIED，布局探针证明 parent_path 偏移错误 | 修正 Version 1 的 parent_path@40 |
| 对真实 HZD 直接假设所有配置目录已隔离 | 真实监控证明宿主路径仍在变化 | 先做合成文件测试，再要求真实 HZD 出现 FILE_REWRITE |
| 双击差分 VHD 后执行初始化/格式化 | 用户确认分区、挂载和游戏都正常，初始化可能破坏差分盘 | 不初始化、不格式化，手动入口应先建立 SMB parent 会话 |

### 保留或改造的方案

- Early-Bird 注入保留。
- MinHook 保留。
- SMB 连接重试保留。
- VHD parent 差分盘保留。
- Registry hive 隔离保留。
- C:\Windows、Program Files 直通保留。
- C/D 盘文件路径重定向在原有规则体系上扩展。
- game_data_root 保持向后兼容，同时新增外部状态库父目录语义。

## 5. 最小成功链路

| 步骤 | 实现位置 | 验证方式 |
|---|---|---|
| VHD parent 连接并创建差分盘 | runtime/src/disk.rs：smb_connect、create_diff_vhd | mount 命令输出 [STEP-1]、[STEP-3] |
| Attach 虚拟磁盘 | disk.rs：open_vhd、attach_vhd | [STEP-4] open-attach |
| 找到卷并分配盘符 | disk.rs：find_volume_for_disk、SetVolumeMountPointW | [MOUNT-OK] G: |
| 挂起创建游戏进程 | runtime/src/inject.rs：launch_suspended | inject-poc 不立即退出 |
| 注入 x64 Hook DLL | inject.rs：inject_into_process 或 inject_into_process_early_bird | HOOK_DLL_PRESENT |
| 初始化 Hook | hook/src/init.c：gvhook_init | RULES_LOADED 12 |
| 注入子进程 | hook/src/proc.c | CHILD_INJECTED pid=... |
| 重写注册表路径 | hook/src/reg.c | REG_REWRITE |
| 重写文件路径 | hook/src/file.c：NtCreateFile、NtOpenFile | 合成测试中的 FILE_REWRITE |
| 游戏退出并卸载 hive | runtime/src/run.rs、hive.rs | RUN-OK、宿主 HKCU 无残留 |

真实 Windows POC 的最小注入链路是：

G:\HorizonZeroDawnRemastered.exe
    ↓
launch_suspended
    ↓
Early-Bird APC / LoadLibraryW
    ↓
gvhook_init
    ↓
RULES_LOADED + HOOK_DLL_PRESENT
    ↓
子进程注入
    ↓
REG_REWRITE / FILE_REWRITE
    ↓
游戏使用隔离后的状态

当前最后一项需要补充真实 HZD 验收：

$log = Join-Path $env:LOCALAPPDATA 'GameAtlas\logs\horizon-zero-dawn-remastered.log'

Get-Content -LiteralPath $log -Tail 0 -Wait |
    Select-String 'RULES_LOADED|HOOK_DLL_PRESENT|REG_REWRITE|FILE_REWRITE|FILE_READTHROUGH|INIT_FAILED'

真正确认文件沙箱成功，至少应该看到：

FILE_REWRITE op=NtCreateFile src=C:\Users\Hao\... dst=G:\GameData\...
FILE_REWRITE op=NtCreateFile src=D:\... dst=G:\GameData\HostDrives\D\...

而不是只看到：

HOOK_DLL_PRESENT
REG_REWRITE

## 6. 与 DeepSeek 失败过程的可比差异

### 有证据支持的部分

#### 1. 存在错误结论累积

远端 feature/gamevhd-runtime-archive 的历史中有：

9b05c44 feat(gamevhd): TUI 启动器重构收尾——归档 runtime 路线到本分支
a0bb2a8 docs(gamevhd): 标注本分支不再维护

9b05c44 的说明把以下现象总结为 runtime 路线不可行：

注入被游戏检测
游戏主动退出 code=0
管理员权限启动崩溃

但之后在真实 Windows GPU 环境下，Early-Bird 路径成功让游戏启动，并出现：

HOOK_DLL_PRESENT
CHILD_INJECTED pid=18004
REG_REWRITE

这至少证明"某一次注入失败"不能直接推广为"整个注入路线不可行"。

#### 2. 环境改变后没有沿用同一验收标准

前期环境是：

Linux VM + Wine + virgl

后期环境是：

Windows 真机 + 真实 GPU

Wine 中的页面执行错误不能直接推断 Windows 真机的 Hook 结果。

#### 3. 验证方式从启动级升级到了路径级

有效的验证不是：

游戏窗口出现
进程存在
DLL 名字出现在模块列表

而是：

具体 API 被命中
具体源路径和目标路径被记录
宿主源目录没有产生新的写入

这是这次脱困中最重要的流程差异。

#### 4. 分支和工作树隔离减少了污染

本次使用：

main: 保持不动
/tmp/GameManager-gamevhd-poc: 独立 worktree

并在后续创建：

feature/gamevhd-external-data-root

提交：

f557683 feat(gamevhd): 支持按游戏目录隔离外部状态库

因此没有通过来回切换破坏用户的 main 工作。

### 目前不能证明的部分

- 不能证明 DeepSeek v4flash Max 内部具体"想了什么"。
- 不能证明所有失败补丁都是 DeepSeek 产生的。
- 不能证明它一定没有使用真实 Windows 测试。
- 不能证明模型能力差异本身是唯一原因。
- 不能证明上下文污染直接造成了每一个具体错误。

### 基于事实的合理推断

更可能的差异是工作方式：

- 没有把"注入成功、注册表成功、文件重定向成功"拆成独立验收目标。
- 在根因未确认时，容易继续追加兼容性补丁。
- 把 Wine/虚拟 GPU 现象和 Hook 逻辑混在一起。
- 使用了旧包或旧日志时，没有先确认产物哈希和构建时间。
- 远端分支的"归档说明"可能让后续工作默认接受了"路线已失败"的结论。
- 对 Windows 原生 API、VHD 差分链、NT API 和 x64 ABI 的细节判断不足，确实可能存在模型能力差异，但代码和日志只能证明结果，不能证明内部原因。

## 7. 可复现交接协议

交给另一个 agent 时，最少提供：

1. 当前 commit、分支、worktree 路径，以及 git status --short。
2. 明确禁止修改 main，指定独立 worktree。
3. VHD parent 的实际路径、SMB 地址、差分盘路径、挂载盘符。
4. 真实游戏 exe 路径、位数、Windows 版本、GPU 和管理员权限状态。
5. 完整注入命令，不要把 --mode early-bird 拆成单独命令。
6. Hook 日志、runtime 日志、文件监控日志和运行时间。
7. 分别验收注入、注册表、文件系统，不把一个 marker 当成全部成功。
8. 先用合成测试程序验证 C/D 路径，再测试真实游戏。
9. VHD 只允许创建差分盘、attach、detach；禁止自动初始化、格式化或删除 backing VHD。
10. 每个已确认根因单独提交，并记录错误码、日志字段和验证命令。

### 一句话突破点

把"游戏启动了"改造成"具体 NT API 捕获到具体宿主路径，并把写入目标改到了 GameData"。

### 最容易让后续 agent 走偏的三个前提

1. 看到 HOOK_DLL_PRESENT 就认为文件沙箱已经完成。
2. 看到 RULES_LOADED 12 就认为所有文件和注册表状态都隔离了。
3. 看到 Wine/虚拟机崩溃就认为注入路线或 VHD 已经失败。

### 顽固问题脱困检查清单

1. 先记录 commit、分支、worktree 和未提交文件。
2. 确认当前测试产物不是旧 DLL 或旧 runtime。
3. 先验证目标环境是否具备真实 GPU 和正确权限。
4. 分别测试 VHD、进程注入、Hook 初始化、注册表、文件系统。
5. 每个假设都配一个能证伪它的日志或命令。
6. 优先看源路径和目标路径，不只看进程是否启动。
7. 检查 x64/x86 位数和子进程链。
8. 用合成程序先覆盖 C 盘、D 盘、读、写、创建、删除。
9. 不要对正常的差分 VHD 执行初始化或格式化。
10. 真实游戏没有 FILE_REWRITE 之前，不宣布文件沙箱完成。
