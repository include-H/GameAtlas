| # | 错误码 | 症状 | 根因 | 修复 |
|---|---|---|---|---|
| 1 | 0x3 (3) | CreateVirtualDisk ERROR_PATH_NOT_FOUND | diff 父目录不存在（API 不自动建） | mount_vhd 先 `create_dir_all` 父目录 |

## 2. 关键取证手段

### 2.1 diskpart 对照实验（区分环境 vs 参数）

diskpart 底层同样调 CreateVirtualDisk。用它创建差分盘作为**环境基线**：

```powershell
'create vdisk file="C:\Users\Hao\GameAlts\dp-test.vhd" parent="D:\1.vhd"' | diskpart
```

结果：**成功**（"DiskPart 已成功创建虚拟磁盘文件"）→ 环境（SMB 凭据 / 文件权限 / 磁盘格式）全部 OK，问题收敛到**我们自己的调用参数**。这排除了无数环境假设。

### 2.2 layout_probe.exe（mingw C 布局对照工具）

手写 FFI 结构体布局必须与真实头文件一致——编译期断言可能"自洽但错误"（断言的是自己算的偏移）。用 mingw 交叉编译 C 程序打印真实偏移：

```c
// mingw 实测（x64）：
CREATE_VIRTUAL_DISK_PARAMETERS size: 128
  Version1.ParentPath offset: 40   ← 关键！不是 48
  Version1.SourcePath offset: 48
```

**这就是 0x5 的真凶**：我按 V2 的 padding 习惯给 V1 加了 `_pad2`，把 parent_path 从 40 推到 48。V2 里 PhysicalSectorSize 结束于 44（非 8 倍数）才需要 pad；V1 里 SectorSize 结束于 40（恰为 8 倍数）不需要。**教训：V1/V2 的 padding 规则不同，不能照抄；布局必须实测对照，不能只信自己的计算。**

### 2.3 分步 STEP 日志（定位崩溃/错误步骤）

mount_vhd 每步打 ASCII `[STEP-n]` 到 stdout：SMB → 建目录 → create → attach → 物理路径 → 卷匹配 → 定盘符。崩溃（0xC0000005）或错误时一眼定位到具体 API。**用 ASCII marker 而非中文**（PS 5.1 GBK 控制台中文乱码）。

## 3. 微软官方文档对照（不猜，查文档）

### 3.1 CREATE_VIRTUAL_DISK_PARAMETERS 字段约束

| 字段 | 约束（文档原文） | 我们踩的坑 |
|---|---|---|
| Version1.SectorSizeInBytes | **Must be set to 512** | 曾传 0 |
| Version1.BlockSizeInBytes | 0 (DEFAULT) / 0x80000 / 0x200000 | 传 0 OK |
| Version1.MaximumSize | ParentPath 指定时必须 0 | 传 0 OK |
| Version1.ParentPath / SourcePath | 互斥 | OK |

### 3.2 VIRTUAL_DISK_ACCESS_MASK（官方枚举）

```
NONE=0x00000000  ATTACH_RO=0x00010000  ATTACH_RW=0x00020000
DETACH=0x00040000  GET_INFO=0x00080000  CREATE=0x00100000
METAOPS=0x00200000  READ=0x000d0000  ALL=0x003f0000  WRITABLE=0x00320000
```

- CreateVirtualDisk 文档：**Version 2 必须用 NONE**（隐含 V1 不是 NONE）
- 微软官方示例 CppVhdAPI：**V1 创建用 VIRTUAL_DISK_ACCESS_CREATE**
- 官方 Windows-classic-samples：VHDX 用 VERSION_2 + ACCESS_NONE

**结论：access mask 与参数版本强绑定**——V1/VHD 用 CREATE，V2/VHDX 用 NONE。之前 V1 用 NONE 是 0x5 的第二层原因。

### 3.3 GetVirtualDiskPhysicalPath

- `DiskPath` 是 `[out, optional]`，**无『传 NULL 拿大小』语义**（不像 GetModuleFileName）
- 正确用法：单次调用 + 足够缓冲（MAX_PATH=260 字符）
- handle 必须含 VIRTUAL_DISK_ACCESS_GET_INFO 标志打开（ALL 含此位，OK）
- 输出形如 `\\?\PhysicalDriveN`

### 3.4 OpenVirtualDisk（文档要求）

- 打开**永久挂载（PERMANENT_LIFETIME）**的盘时，access mask 必须含 `VIRTUAL_DISK_ACCESS_DETACH`(0x40000) → 用 ALL（含此位）✓
- 类型（VHD/VHDX）必须与文件匹配：按扩展名 detect → device_id

### 3.5 卷枚举 IOCTL

- `IOCTL_VOLUME_GET_VOLUME_DISK_EXTENTS`：NULL in / out buffer + size + bytes returned + NULL overlapped
- **卷设备句柄必须用 `dwDesiredAccess=0` 打开**（GENERIC_READ 被卷拒绝），share = FILE_SHARE_READ|WRITE，OPEN_EXISTING
