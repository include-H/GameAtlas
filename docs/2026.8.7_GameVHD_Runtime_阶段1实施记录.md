## 2. 阶段 4：磁盘层（disk.rs）

### 2.1 能力清单（v2 定案 §3.2，替代 diskpart）

| API | 用途 | 关键点 |
|---|---|---|
| `WNetAddConnection2W` | SMB 只读连接 | 重试 ×N（NAS 休眠唤醒）；85/87 幂等已连接 |
| `CreateVirtualDisk` | 差分盘创建 | parent=UNC；**VHD/VHDX 结构不同**（见 §4.3） |
| `OpenVirtualDisk` | 打开已有差分盘 | VIRTUAL_DISK_ACCESS_ALL |
| `AttachVirtualDisk` | 挂载 | **必须 PERMANENT_LIFETIME**（句柄关闭后挂载保持） |
| `DetachVirtualDisk` | 卸载 | 幂等容忍 INVALID_STATE(0xC03A001C) |
| `GetVirtualDiskPhysicalPath` | 物理盘路径 | `\\?\PhysicalDriveN` → 解析盘号 |
| `FindFirstVolume`+IOCTL | 卷枚举匹配物理盘 | `IOCTL_VOLUME_GET_VOLUME_DISK_EXTENTS`(0x560000) |
| `DefineDosDeviceW` | 显式分配盘符 | 首选字母优先，否则 D..Z 首个空闲 |

## 3. 阶段 5 起步（manifest / selftest / scan）

### 3.1 manifest.rs——尾部配置块（v2 定案 §3.1）

```
[launcher.exe][config JSON][GVHDCFG\0 8B][u32le json_len 4B]
```

- 定位：严格尾部 12B 优先，回退扫描最后 4KB（容忍签名/填充块）
- 校验：magic、长度范围（0 < len ≤ 64KB）、未知字段/重复键拒绝
- 字段：game_id / title / base_vhd / diff_name（必填）+ smb_user / smb_pass / exe_hint / skip_cache_dirs（可选）
- 12 个单测：round-trip、扫描回退、坏长度、缺字段、转义、Unicode

### 3.2 `--selftest` 自检（v2 定案 §5.1）

- footer 自定位/解析（内存样本）
- 规则生成（%USERPROFILE%/%TEMP% 锚点，12 条）
- PE 位数探测（本二进制）
- 跨平台可跑，任一项失败退出码 1；真机已验证三项全 PASS

### 3.3 scan.rs 增强（v2 定案 §3.7）

- 噪声过滤扩展：`unins*`/`setup*`/`install*`/`vcredist*`/`dxsetup` 前缀 + `redist`/`redistributable`/`directx`/`vcredist`/`support` 目录段
- 排序：深度浅优先 + 同深度体积大优先
- box.json 记忆：`remembered_exe_exists`/`resolve_remembered`/`to_relative`（记忆失效回退重扫）

## 4. 真机排错记录（教训沉淀）

> 排错方法论：症状归类 → 取证优先 → 分层归因 → 一次一变量。以下 4 个问题全部在用户真机（Windows 11 + PS 5.1）暴露，均通过取证定位而非猜测。

### 4.1 断言脚本解析失败：UTF-8 无 BOM × PS 5.1 GBK 解码

**现象**：`assert_mount.ps1` 报 `表达式或语句中包含意外的标记"}"`、`字符串缺少终止符`，且报错文本中文显示为乱码（`盘符` → `鐩樼`）。

**根因**：PowerShell 5.1 读取 .ps1 不识别 UTF-8 无 BOM，按系统 ANSI 代码页（中文系统 = GBK）解码。UTF-8 中文多字节序列被 GBK 错误解释后，引号/花括号配对错乱，语法分析失败。

**修复**（两层）：
1. `c7b8431`：5 个 assert_*.ps1 加 UTF-8 BOM（EF BB BF）
2. `2121728`：**断言脚本全部改纯 ASCII**（注释/消息/断言全英文）+ runtime 成功输出改 ASCII marker。彻底消除编码依赖——PS 7+ 也默认 UTF-8，但 GBK 控制台永远会乱码中文，机器解析必须 ASCII。

### 4.2 `$Args` 自动变量劫持：参数静默丢空

**现象**：BOM 修复后脚本能解析，但 runtime 报 `缺少子命令`——参数根本没传进去。

**根因**：`function Invoke-Runtime { param([string[]]$Args) ... & $RuntimeExe @Args ... }`。**`$Args` 是 PowerShell 自动变量**（未绑定参数集合），用作 param 名时 `@Args` 展开被自动变量语义劫持成空数组。

**修复**：参数名改 `$ArgList`。这是 PS 语言级陷阱，与编码无关。

### 4.3 CreateVirtualDisk 0x570 ERROR_FILE_CORRUPT：VHD/VHDX 参数结构错配

**现象**：挂载 `.vhd` 基础盘，CreateVirtualDisk 返回 0x570（1392, ERROR_FILE_CORRUPT）。

**根因**：初始实现写死 VHDX：`VIRTUAL_STORAGE_TYPE_DEVICE_VHDX`(3) + `CREATE_VIRTUAL_DISK_PARAMETERS` Version 2（128B）。用 VHDX 解析器读 VHD 文件必然报损坏。**VHD 与 VHDX 的差分盘参数结构不同**：
- VHD：`DEVICE_VHD`(2) + 参数 **Version 1**（64B，无 PhysicalSectorSize/ParentVirtualStorageType/SourceVirtualStorageType/ResiliencyGuid）
- VHDX：`DEVICE_VHDX`(3) + 参数 **Version 2**（128B）

**修复**：新增 `VhdFormat` 枚举 + `detect()` 按 parent 扩展名探测；`create_diff_vhd` 按格式分支构造 V1/V2；布局守护从运行期测试升级为**编译期 const 断言**（`offset_of!`/`size_of`，布局错直接编译失败）。

### 4.4 mount 0x3 ERROR_PATH_NOT_FOUND：diff 父目录缺失

**现象**：`C:\Users\Hao\AppData\Local\GameAtlas\diff\` 首次运行不存在，CreateVirtualDisk 返回 0x3。

**根因**：CreateVirtualDisk 不自动创建父目录；mount_vhd 未先行建目录。

**修复**：mount_vhd 在创建差分盘前对 diff_path 父目录 `create_dir_all`（幂等）。

### 4.5 ⚠️ 未解决：mount 崩溃 0xC0000005 STATUS_ACCESS_VIOLATION（排查中）

**现象**：真实 `.vhd` parent 挂载崩溃，退出码 -1073741819（0xC0000005）。**无任何业务输出**——不是错误返回，是进程级访问违例。

**已排除（取证）**：
- 坏 parent `.vhdx` + 无 SMB 路径正常返回 0x35 → VHDX 结构 + 无 SMB 路径 OK
- 真实 parent `.vhd` + SMB 崩溃 → 锁定 VHD Version 1 结构路径
- SMB 连接本身 OK（第 3 步无 SMB 也崩不了，且第 1 步 SMB 重试日志未出现 → 连接成功）

**当前假设**：VHD Version 1 结构体布局或调用与系统期望不符，导致内核态解析越界。但编译期断言（64B、parent_path@48）已过，与 mingw 头文件一致，矛盾未解。

**进行中的取证**：已给 mount_vhd 加 `[STEP-1..7]` ASCII 分步日志（`9d24bc0` 后的工作区改动），下轮真机重跑即可定位崩溃发生在哪一步（SMB / 建目录 / create / attach / 物理路径 / 卷匹配 / 定盘符）。

**待验证假设**（下一步）：
1. STEP 日志定位崩溃步骤
2. 若崩在 create：怀疑 V1 结构在真机 ABI 与编译期断言不一致（mingw 头文件 vs MSVC 头文件的 ULONGLONG 对齐差异——mingw x86_64 与 MSVC x64 对齐规则应一致，但需真机实证）
3. 备选：`VhdFormat::detect` 对中文路径的扩展名判断是否可靠
